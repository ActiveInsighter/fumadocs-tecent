# n8n document publishing workflow

Import `document-publish.workflow.json` into n8n and leave it inactive until
the environment variables are configured. The Webhook node uses the
production URL generated by n8n:

```text
POST https://<n8n-host>/webhook/anyworkflow-document-publish
```

The Fumadocs server sends `X-Internal-Key`; the first Code node compares it
with `N8N_DOCUMENT_PUBLISH_SECRET`. The workflow never receives the PocketBase
user token from the extension.

## n8n environment variables

Set these on the n8n host/container, then restart n8n:

`compose.document-publishing.override.yml` is a secret-free Compose override
for the existing `/opt/n8n/compose.yml`. Copy it beside that file and start
n8n with both Compose files; provide the values through the host's existing
`.env` without printing or committing that file.

| Variable | Purpose |
| --- | --- |
| `N8N_DOCUMENT_PUBLISH_SECRET` | Matches Fumadocs `N8N_DOCUMENT_PUBLISH_SECRET`. |
| `POCKETBASE_URL` | PocketBase origin, for example `https://pb.any1.tech`. |
| `POCKETBASE_SERVER_TOKEN` | Server-only PocketBase superuser/service token. |
| `NEW_API_BASE_URL` | Aliyun New API OpenAI-compatible origin. |
| `NEW_API_MODEL` | Model used for metadata JSON. |
| `NEW_API_API_KEY` | Server-only New API key. |
| `FUMADOCS_BASE_URL` | Public Fumadocs origin. |
| `FUMADOCS_BLOB_UPLOAD_KEY` | Matches Fumadocs `FUMADOCS_BLOB_UPLOAD_KEY`. |
| `GITHUB_OWNER` | Fumadocs repository owner, normally `ActiveInsighter`. |
| `GITHUB_REPO` | Fumadocs repository name, normally `fumadocs-vercel`. |
| `GITHUB_BRANCH` | Fumadocs publish branch, normally `main`. |
| `GITHUB_TOKEN` | Fine-grained token with Contents: write on the Fumadocs repository and Actions: write on the mdTOpdf repository. |
| `MDTO_PDF_SUPABASE_URL` | Supabase project URL used by the mdTOpdf repository. |
| `MDTO_PDF_SUPABASE_SERVICE_KEY` | Server-only Supabase secret key (`sb_secret_...`) or legacy service-role JWT. |
| `MDTO_PDF_SUPABASE_USER_ID` | UUID of the mdTOpdf Supabase Auth user that owns n8n-created jobs. |
| `MDTO_PDF_SUPABASE_BUCKET` | Private Storage bucket used by mdTOpdf; defaults to `pdf-jobs`. |
| `MDTO_PDF_THEME` | Renderer theme; defaults to `chatgpt-light`. |

The mdTOpdf repository, workflow, and branch are intentionally fixed in the
workflow source:

```text
ActiveInsighter/md-to-pdf
main
.github/workflows/build-pdf-api.yml
```

The workflow uses `$env.*` in Code and HTTP Request nodes. If the n8n install
blocks environment access inside nodes, set
`N8N_BLOCK_ENV_ACCESS_IN_NODE=false` according to the n8n deployment policy.
Set `N8N_DEFAULT_BINARY_DATA_MODE=filesystem` so the downloaded PDF is not
kept in process memory longer than necessary. Do not put any secret values
into the exported JSON.

## Behavior

- The webhook body contains only the deterministic event envelope from Fumadocs.
- PocketBase is read with the server token and the message owner is checked
  against the event owner before any artifact is generated.
- A published document with the same checksum is a no-op. An in-flight document
  with the same checksum is also ignored to prevent concurrent uploads. A
  failed document with the same checksum reuses its version, so a rerun does
  not create a second version.
- Markdown is cleaned of frontmatter/import/export/raw HTML before it becomes
  MDX. The original AI answer is still preserved in `aw_messages`.
- The document is written to `aw_documents` with `status=processing` before
  the PDF job starts, so failures can be recorded by the error workflow.
- mdTOpdf is called only through its private Supabase-backed job API: n8n
  creates `pdf_jobs`, uploads `jobs/{uuid}/input.md`, advances the job through
  `uploaded` and `queued`, dispatches the fixed GitHub Action with `job_id`,
  polls `pdf_jobs`, and downloads `jobs/{uuid}/output.pdf` after completion.
  No Markdown file is committed to GitHub, and no mdtopdf renderer is
  installed on the cloud server.
- Both artifacts are uploaded using exact signed `Content-Type` values. The
  workflow upserts artifact records by `(document, version, format)`.
- GitHub Contents API receives a base64-encoded MDX file and the existing file
  SHA when the page already exists.
- The document is marked `published` only after both artifact records and the
  GitHub commit have succeeded.

Import `document-publish-error.workflow.json` as the Error Workflow for the
main workflow. It extracts the last owner-scoped document record from the
saved execution data and writes `status=failed` plus a bounded `lastError` to
`aw_documents`. The main workflow saves error execution data and can be safely
re-run with the same event after fixing the failed component.
