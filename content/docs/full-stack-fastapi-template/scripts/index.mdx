<Callout type="idea" title="目录定位">

根脚本负责跨越多个工作区或服务的流程。单独属于后端的测试启动脚本仍放在 `backend/scripts/`。

</Callout>

## 如何组织

| 脚本 | 范围 | 结果 |
| --- | --- | --- |
| `add_latest_release_date.py` | 发布文档 | 补齐最新版本日期 |
| `generate-client.sh` | 后端 → 前端 | 更新 OpenAPI 生成客户端 |
| `test-local.sh` | 本地 Docker | 启动栈并运行后端测试 |
| `test.sh` | CI/标准 Docker | 构建、测试、清理完整栈 |

## 组织原则

- 跨服务流程放根 scripts，单服务实现留在服务目录。
- 失败立即退出，避免继续使用半成品。
- 脚本应可重复执行并清理旧容器。
- 命令行参数通过 `"$@"` 原样转交测试层。
- 本地便利脚本与 CI 脚本明确区分清理策略。
