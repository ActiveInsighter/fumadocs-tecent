<Callout type="warn" title="文件定位">

该文件是构建产物，不是手写业务源码。它将 `routes` 目录中的 Route 导出编织成一棵树，并生成 Link、navigate、Route.useParams 等 API 所需的精确类型。

</Callout>

## 这个文件负责什么

- 导入所有文件路由。
- 为路由绑定 id、path 和 parent。
- 生成 fullPath、to、id 类型映射。
- 扩展 TanStack Router 的 FileRoutesByPath。
- 组装布局子树和根路由子树。
- 导出最终类型化 routeTree。

## 阅读重点

- 不要手工修改；保存后也会在下一次生成时丢失。
- `_layout` 不出现在 URL 中，但作为父节点提供认证外壳。
- FullPath 是用户看到的 URL，Id 保留文件层级，二者用途不同。
- `@ts-nocheck` 和 eslint disable 是生成器的选择，不应复制到普通源码。
- 代码审查时重点关注路由文件变化，生成文件可视项目策略选择是否提交。

## Twoslash：合法路径联合类型

```ts twoslash
// ---cut-start---
type AppPath =
  | '/'
  | '/login'
  | '/recover-password'
  | '/reset-password'
  | '/signup'
  | '/admin'
  | '/items'
  | '/settings'
// ---cut-end---
declare const path: AppPath
//            ^?
```

这类联合类型使 `navigate({ to: ... })` 在编译期拒绝拼写错误，而不是等到运行时才发现 404。
