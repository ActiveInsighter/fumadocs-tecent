<Callout type="idea" title="文件定位">

这是整个前端视觉系统的单一入口。组件只使用 `bg-background`、`text-muted-foreground` 等语义类，具体颜色由这里的 CSS 变量在浅色和深色主题中切换。

</Callout>

## 这个文件负责什么

- 导入 Tailwind CSS 与动画工具。
- 定义 class 驱动的 dark 变体。
- 把 CSS 变量注册为 Tailwind token。
- 设置浅色与深色语义色。
- 定义图表和侧边栏专用变量。
- 统一全局边框、焦点环、背景和指针行为。

## 与其他模块的关系

| 模块 | 关系 |
| --- | --- |
| `ThemeProvider` | 在根元素切换 dark 类。 |
| `所有 UI 组件` | 消费 background、primary、muted 等语义类。 |
| `Tailwind CSS 4` | 通过 @theme inline 暴露 token。 |
| `tw-animate-css` | 为 Dialog、Tooltip 等提供状态动画。 |

## 主要令牌分组

| 分组 | 变量示例 | 使用场景 |
| --- | --- | --- |
| 页面 | `background`, `foreground` | body 与正文 |
| 容器 | `card`, `popover` | 卡片、菜单、通知 |
| 交互 | `primary`, `secondary`, `accent` | 按钮、选中、hover |
| 状态 | `destructive`, `ring`, `border`, `input` | 危险操作、焦点和边界 |
| 数据 | `chart-1` ... `chart-5` | 图表系列 |
| 导航 | `sidebar-*` | 侧边栏独立主题 |

## 阅读重点

- OKLCH 的三个主要参数分别是亮度、色度和色相，较适合构建感知均匀主题。
- 组件应引用语义色，不要在业务 JSX 中散落具体 OKLCH 值。
- 浅色和深色必须定义相同变量集合，避免切换时回退到旧值。
- `@apply border-border outline-ring/50` 会影响所有元素，新增第三方组件时要检查继承效果。
- 侧边栏有独立 token，可在不改变主页面卡片色的情况下独立调色。

## 修改主题时的检查顺序

<Steps>
  <Step>先调整 `:root` 和 `.dark` 的变量值，不直接改组件。</Step>
  <Step>检查 primary/foreground 对比度以及 destructive 状态。</Step>
  <Step>检查 Card、Popover、Sidebar 等不同表面层级。</Step>
  <Step>验证 focus ring、disabled、hover、selected 等交互状态。</Step>
  <Step>最后在移动端和深色模式中进行视觉回归。</Step>
</Steps>
