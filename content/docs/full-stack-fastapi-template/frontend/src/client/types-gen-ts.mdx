<Callout type="idea" title="文件定位">

这个文件是前后端类型契约的静态镜像。组件表单、表格行、Mutation 参数和 SDK 返回值都能直接复用生成类型，从而让后端字段变化在编译阶段暴露。

</Callout>

<Callout type="warn" title="自动生成文件">

该文件由 OpenAPI 客户端生成器维护。本文在代码块中增加的注释只用于学习；实际项目重新运行生成脚本时，手工改动可能被覆盖。需要改变长期行为时，应优先修改 OpenAPI 描述、生成器配置或生成模板。

</Callout>

## 这个文件负责什么

- 定义 Item、User、Token、Message 等数据模型。
- 区分 Create、Update、Public 和集合响应。
- 为每个端点生成 `*Data` 输入对象。
- 为每个端点生成 `*Response` 返回别名。
- 表达可选字段、nullable 字段和 unknown 扩展上下文。

## 执行思路

1. Pydantic 模型和路由响应生成 OpenAPI。
2. 生成器映射为 TypeScript 属性与联合类型。
3. sdk.gen.ts 使用端点 Data/Response 类型。
4. 业务组件通过 `@/client` 复用模型。

## 与其他模块的关系

| 模块 | 关系 |
| --- | --- |
| `backend/app/models.py` | 类型定义的源头。 |
| `sdk.gen.ts` | 消费端点输入和返回类型。 |
| `schemas.gen.ts` | 同一契约的运行时表示。 |
| `Forms / Tables` | 直接使用 UserPublic、ItemPublic 等类型。 |

## 类型命名规律

| 后缀/前缀 | 含义 | 示例 |
| --- | --- | --- |
| `Create` | 创建请求所需字段 | `ItemCreate` |
| `Update` | 部分更新字段，多数可选 | `UserUpdate` |
| `Public` | 可以返回给客户端的公开字段 | `UserPublic` |
| `*sPublic` | 分页集合 `{ data, count }` | `UsersPublic` |
| `*Data` | 某个端点的所有输入参数 | `UsersUpdateUserData` |
| `*Response` | 某个端点的返回类型 | `ItemsReadItemsResponse` |

<Callout type="info" title="可选与可空不是同一件事">

`field?: string` 表示属性可以不存在；`field: string | null` 表示属性必须存在但值可以为空；`field?: string | null` 同时允许缺失和空值。表单与 PATCH 请求中要特别区分。

</Callout>

## 阅读重点

- 生成类型是编译期保障，不能替代对服务端响应的运行时验证。
- 更新类型普遍使用可选字段，适合 PATCH 语义；提交前应移除不想更新的空值。
- `created_at?: string | null` 仍是字符串，需要在 UI 中显式解析为 Date。
- 不要复制生成类型到业务目录；应直接导入或使用交叉类型扩展。
