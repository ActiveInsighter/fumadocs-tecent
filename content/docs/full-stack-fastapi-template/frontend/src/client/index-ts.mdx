<Callout type="idea" title="文件定位">

业务组件通常只从 `@/client` 导入内容，而不直接访问 `core/`、`sdk.gen.ts` 或 `types.gen.ts`。这个桶文件为生成客户端提供稳定的公共 API。

</Callout>

<Callout type="warn" title="自动生成文件">

该文件由 OpenAPI 客户端生成器维护。本文在代码块中增加的注释只用于学习；实际项目重新运行生成脚本时，手工改动可能被覆盖。需要改变长期行为时，应优先修改 OpenAPI 描述、生成器配置或生成模板。

</Callout>

## 这个文件负责什么

- 重新导出结构化错误和取消能力。
- 暴露 OpenAPI 运行时配置。
- 导出所有服务类和端点方法。
- 导出所有请求/响应数据类型。

## 执行思路

1. 生成器根据后端 OpenAPI 文档生成多个文件。
2. 桶文件将可用能力聚合到一个模块。
3. 业务层通过路径别名 `@/client` 导入。
4. 重新生成后，业务层导入路径保持稳定。

## 与其他模块的关系

| 模块 | 关系 |
| --- | --- |
| `sdk.gen.ts` | 业务服务类。 |
| `types.gen.ts` | 端点和数据模型类型。 |
| `core/*` | 请求运行时。 |
| `React components / hooks` | 只依赖这一公共入口。 |



## 带注释源码

> 原始路径：`frontend/src/client/index.ts`。以下仅增加学习性注释，不改变程序行为。

```ts title="index.ts" lineNumbers
// This file is auto-generated by @hey-api/openapi-ts
// 对外暴露统一异常，业务层无需知道 core 目录结构。
export { ApiError } from './core/ApiError';
// 暴露可取消 Promise 与专用取消错误。
export { CancelablePromise, CancelError } from './core/CancelablePromise';
// 应用启动时通过这里配置 BASE、TOKEN 与拦截器。
export { OpenAPI, type OpenAPIConfig } from './core/OpenAPI';
// 业务调用入口：ItemsService、UsersService、LoginService 等。
export * from './sdk.gen';
// 请求与响应 DTO、端点参数和返回类型。
export * from './types.gen';
```

## 阅读重点

- 桶文件能减少深层相对路径，但也要避免导出内部不稳定实现。
- `export *` 适合生成代码；手写大型项目中需要注意重名冲突。
- 应用层配置 OpenAPI 时也应从该入口导入，保持一致。
