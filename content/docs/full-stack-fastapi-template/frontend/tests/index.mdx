## 如何组织

测试分成三层：

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 配置层 | `config.ts`, `auth.setup.ts` | 注入环境并生成登录快照 |
| 场景层 | `*.spec.ts` | 从用户视角描述业务行为 |
| 工具层 | `utils/*` | 创建数据、轮询邮件、复用用户动作 |

<Callout type="info" title="测试金字塔中的位置">

这些是数量较少但覆盖链路最完整的 E2E 测试。纯函数、校验器和组件细节仍应由更快的单元/组件测试承担。

</Callout>

## 组织原则

- 每个 spec 聚焦一个页面或业务域。
- 默认复用认证快照，匿名场景显式清空。
- 优先可访问定位器，必要时使用稳定 test id。
- 随机数据降低唯一约束冲突。
- 断言用户可观察结果，不绑定实现细节。
- 跨文件复用动作放入 utils，避免 spec 变成工具函数集合。
