<Callout type="idea" title="文件定位">

该文件有意保持极简。现代 Python 支持命名空间包，但显式 `__init__.py` 能让包边界更清晰，并兼容更多工具。

</Callout>

## 这个文件解决什么问题

- 明确 `app.core` 是可导入包。
- 避免在包初始化阶段执行数据库连接等副作用。
- 可在未来集中导出稳定的公共接口。

## 核心执行流程

1. Python 导入 `app.core`。
2. 解释器执行本文件。
3. 当前不执行额外逻辑，随后按需导入子模块。

## 与其他模块的关系

- **`config.py`**：配置对象。
- **`db.py`**：数据库引擎。
- **`security.py`**：安全函数。

## 带注释源码

> 原始路径：`backend/app/core/__init__.py`。以下仅增加学习性注释，不改变程序逻辑。

```python title="__init__.py" lineNumbers
# 该文件刻意不执行任何初始化逻辑。
```

## 阅读重点

- 空文件不是“没用”，它表达包边界。
- 不要为了方便在这里导入所有子模块，否则可能引入循环依赖和启动副作用。
