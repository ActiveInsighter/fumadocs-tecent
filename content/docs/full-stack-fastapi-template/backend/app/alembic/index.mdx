## 迁移工作流

<Steps>
  <Step>
    ### 修改 SQLModel
    先在 `models.py` 中表达目标数据库结构。
  </Step>
  <Step>
    ### 生成候选迁移
    Alembic 比较 `SQLModel.metadata` 与当前数据库，生成 `upgrade()` / `downgrade()` 草稿。
  </Step>
  <Step>
    ### 人工审查脚本
    特别检查数据迁移、约束名称、非空字段和破坏性操作；自动生成并不等于一定安全。
  </Step>
  <Step>
    ### 执行并验证
    使用 `alembic upgrade head` 升级，再在测试数据库验证回滚与数据完整性。
  </Step>
</Steps>

```mermaid
flowchart LR
  Models[SQLModel 模型] --> Compare[Alembic autogenerate]
  DB[(当前数据库)] --> Compare
  Compare --> Revision[versions/ 新迁移]
  Revision --> Review[人工审查]
  Review --> Upgrade[upgrade]
  Upgrade --> NewDB[(新结构)]
  NewDB --> Downgrade[downgrade 验证]
```

<Callout type="warn" title="迁移不是普通代码重构">

删除列、替换主键和新增非空约束都可能造成数据丢失或长时间锁表。生产迁移必须先备份、评估数据量，并设计可回滚方案。

</Callout>
