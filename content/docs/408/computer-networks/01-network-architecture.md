## 二、1.1 计算机网络概述

### 1. 计算机网络到底是什么？

资料中的定义是：

**将众多分散、自治的计算机系统，通过通信设备与线路连接起来，并依靠软件实现资源共享和信息传递**。

这个定义真正要理解三个词。

#### （1）分散

机器可能分布在不同地方。

比如：

```text
北京服务器
    │
互联网
    │
上海PC
    │
广州手机
```

#### （2）自治

每台计算机自己都可以独立运行。

网络中的计算机不是传统大型机下面完全依赖主机的“哑终端”。

#### （3）通信 + 资源共享

网络最核心解决两件事情：

```text
我怎么找到你？
       ↓
我怎么把数据送给你？
```

然后才能进一步实现网页、邮件、文件传输、视频等应用。

## 三、internet 和 Internet

这是很典型的小选择题考点。

#### internet

普通名词。

意思是：

> 多个网络互相连接形成的网络。

不要求必须采用 TCP/IP。

#### Internet

专有名词。

特指我们今天使用的全球互联网，并采用 TCP/IP 协议族。

所以可以记：

> **internet 是一种结构，Internet 是那个具体的全球网络**。

## 四、计算机网络的组成

资料给了三种观察方式。

### 1. 从组成部分看

```text
计算机网络
├─ 硬件
├─ 软件
└─ 协议
```

硬件：

- 主机
- 路由器
- 交换机
- 双绞线
- 光纤
- 网卡等

软件：

- 浏览器
- 邮件程序
- FTP 程序等

协议：

> 网络中的“交通规则”。

没有协议，即使两个设备物理上接在一起，也未必能正确通信。

## 五、边缘部分和核心部分

这个概念非常重要，因为后面的网络知识基本都建立在这张图上。

```text
主机A                           主机B
 │                              │
 │          网络核心             │
 └──路由器──路由器──路由器──────┘
 ↑                              ↑
边缘                            边缘
```

### 边缘部分

主要是：

- 主机
- 手机
- PC
- 服务器

也就是用户直接使用的设备。

### 核心部分

主要是：

- 路由器
- 网络
- 高速链路

核心部分的主要任务不是“运行你的应用程序”，而是：

> **把分组从一个地方转发到另一个地方**。

## 六、通信子网与资源子网

又是一组容易混淆的概念。

#### 通信子网

负责：

> **怎么把数据送过去**。

包括：

- 传输介质
- 通信设备
- 通信协议

#### 资源子网

负责：

> **有什么东西可以给用户使用**。

比如：

- 文件
- 服务器
- 数据库
- 打印机
- 软件资源

所以记成：

```text
通信子网 → 运输系统
资源子网 → 被运输/被访问的资源
```

## 七、计算机网络的主要功能

资料总结为五类。

1. 数据通信
2. 资源共享
3. 分布式处理
4. 提高可靠性
5. 负载均衡

其中最根本的是：

> **数据通信**。

没有通信，后面的共享、分布式处理都无法实现。

## 八、★★★★★ 三种交换方式

这是第 1 章第一个真正意义上的大重点。

三种方式：

```text
电路交换
报文交换
分组交换
```

先抓住本质：

| 方式   | 本质            |
| ---- | ------------- |
| 电路交换 | 先给出独占一条路      |
| 报文交换 | 整封“大信件”逐站转发   |
| 分组交换 | 拆成“小包裹”逐站流水转发 |

资料中特别标注了：电路交换时延在 2025 考查，报文交换时延在 2013、2025 考查，分组交换时延在 2010、2013、2023、2025 多次出现。

## 九、电路交换

传统电话网络是典型例子。

过程必须经历：

```text
建立连接
   ↓
数据传输
   ↓
释放连接
```

假设 A 和 B 通信：

```text
A ── R1 ── R2 ── B
```

开始前，先把：

```text
A → R1 → R2 → B
```

整条通路建立好。

建立后，这条资源基本由 A 和 B 独占。

### 电路交换的最大特点

**建立好以后，中间节点不再进行完整报文的存储转发**。

所以：

#### 优点

- 数据传输时延低
- 顺序一定正确
- 实时性很好
- 通信过程中一般没有线路争用

#### 缺点

最大问题：

> **线路利用率低**。

假设你打电话 10 分钟，但真正讲话只有 3 分钟。

其他 7 分钟你不说话，线路资源仍然给你留着。

计算机通信通常又非常突发：

```text
发送一小段
停
发送一小段
停
```

因此特别不适合长期独占线路。

## 十、报文交换

假设 A 要给 B 发一个很大的报文。

报文交换采用：

> **存储—转发**。

过程：

```text
A
│ 发送整个报文
↓
R1
│ 必须完整收完
│ 存起来
│ 查下一跳
↓
R2
│ 再完整收完
│ 再存起来
↓
B
```

核心：

> 路由器收到**整个报文以后**才能往下一跳发送。

### 为什么报文交换慢？

假设报文长度为 L，链路速率为 R。

一条链路把整个报文发送出去需要：

$$
T_t=\frac{L}{R}
$$

假设经过 k 条等速链路，而且忽略传播、处理、排队时延。

那么总发送时间约为：

$$
T=k\frac{L}{R}
$$

因为：

```text
链路1：完整发一次
链路2：完整发一次
链路3：完整发一次
...
```

不能有效流水。

## 十一、★★★★★ 分组交换

Internet 最重要的基本机制。

假设原始报文：

```text
████████████████████████████
```

先分成：

```text
██████  ██████  ██████  ██████
```

然后每段加上首部：

```text
[首部|数据]
[首部|数据]
[首部|数据]
[首部|数据]
```

最终形成若干个 **Packet（分组）**。

## 十二、分组交换为什么比报文交换快？

关键词：

> **流水线**。

假设两个分组 P1、P2：

```text
         R1              R2
A ────────────────┬────────────── B
```

时间过程：

```text
时间1：
A → P1 → R1

时间2：
A → P2 → R1
          R1 → P1 → R2

时间3：
          R1 → P2 → R2
                     R2 → P1 → B
```

可以发现：

> P1 往第二段走的时候，P2 已经可以在第一段上传输了。

所以多个分组发生流水。

这正是分组交换最关键的思想。

## 十三、★★★★★ 分组交换总时延公式

这是本章必须熟练的公式。

假设：

- 报文一共 X bit
- 分组长度 P bit
- 一共有 k 条链路
- 每条链路速率 R
- 每条链路传播时延 d
- 暂时忽略首部、排队、处理时延

分组数量：

$$
m=\frac{X}{P}
$$

### 第一步：源主机发完所有分组

需要：

$$
\frac{X}{R}
$$

### 第二步：最后一个分组继续通过后面 k−1 条链路

每多经过一段链路，需要：

$$
\frac{P}{R}
$$

因此额外：

$$
(k-1)\frac{P}{R}
$$

### 第三步：传播时延

k 条链路：

$$
kd
$$

所以：

$$
\boxed{
T_{\text{分组}}
=
\frac{X}{R}
+
(k-1)\frac{P}{R}
+
kd
}
$$

也可以写成：

$$
\boxed{
T_{\text{分组}}
=
(m+k-1)\frac{P}{R}+kd
}
$$

这两个式子本质完全一样。

资料中的王道题和模拟题正是反复考这个模型。

## 十四、电路交换与分组交换比较题

假设：

- 电路建立时间为 C
- 总数据量 X
- k 段链路
- 分组 P
- 速率 R
- 每段传播时延 d

电路交换：

$$
T_c
=
C+\frac{X}{R}+kd
$$

分组交换：

$$
T_p
=
\frac{X}{R}
+
(k-1)\frac{P}{R}
+
kd
$$

要求分组交换更快：

$$
T_p<T_c
$$

代入：

$$
\frac{X}{R}
+
(k-1)\frac{P}{R}
+
kd
<
C+\frac{X}{R}+kd
$$

两边约掉共同项：

$$
\boxed{
(k-1)\frac{P}{R}<C
}
$$

这正是资料配套题中的典型考法。

注意这里传播时延为什么消失？

因为：

> 两种方式都经过相同的 k 条链路，因此传播时延一样，比较时抵消。

## 十五、分组是不是越小越好？

不是。

这是很重要的理解题。

分组越小：

#### 好处

流水线效果更明显。

#### 坏处

每个分组都要有首部。

比如：

```text
10000B数据
```

如果每组只有 10B 数据：

```text
会产生1000个分组
```

如果每个首部 20B，那么首部甚至比数据更多。

所以存在折中：

> **分组太大 → 流水效果差**。

> **分组太小 → 首部开销过大**。

资料甚至给出了这类优化型选择题：当报文长度为 M、首部长度为 h、两段链路时，可以通过最优化得到近似最优载荷长度。

在两段链路模型下：

$$
T=
\left(
\frac{M}{x}+1
\right)
\frac{x+h}{R}
$$

展开后，只考虑与 x 有关的部分：

$$
f(x)=x+\frac{Mh}{x}
$$

令其最小，可得到：

$$
\boxed{x=\sqrt{Mh}}
$$

这类题不用死背结论，掌握“**分组数量 × 每分组长度 + 流水尾巴**”这个建模思想更重要。

## 十六、三种交换方式最终比较

| 特征     | 电路交换 | 报文交换 | 分组交换     |
| ------ | ---- | ---- | -------- |
| 建立连接   | 要    | 不要   | 通常不要     |
| 线路独占   | 是    | 否    | 否        |
| 存储转发   | 否    | 是    | 是        |
| 存储单位   | —    | 整个报文 | 分组       |
| 缓存要求   | 低    | 最大   | 较小       |
| 流水线    | —    | 差    | ★好       |
| 线路利用率  | 低    | 高    | 很高       |
| 实时性    | 好    | 差    | 较好       |
| 首部开销   | 少    | 有    | 更多       |
| 出错重传代价 | —    | 大    | 小        |
| 典型应用   | 电话   | 历史系统 | Internet |

一句话：

> **连续、长期、大量数据 → 电路交换有优势**。

> **突发式计算机通信 → 分组交换最合适**。

## 十八、按传输方式分类

### 广播式网络

一个节点发出的数据，多个节点可能都能收到。

比如经典共享式局域网。

核心：

> **大家共享信道**。

### 点对点网络

一条链路连接一对节点。

数据往往要经过：

```text
A → R1 → R2 → R3 → B
```

逐跳传输。

## 十九、拓扑结构

主要四种：

```text
总线
星形
环形
网状
```

#### 总线型

大家连一条公共总线。

优点：

- 便宜
- 简单

缺点：

- 总线故障影响大
- 负载高时效率低

#### 星形

```text
    A
    |
B--交换机--C
    |
    D
```

优点：

- 易管理
- 单个边缘线路坏了影响有限

缺点：

> 中央设备很重要。

#### 环形

节点形成环。

#### 网状

节点间存在多条路径。

广域网常见。

优点：

- 可靠
- 容错好

缺点：

- 成本高
- 路由复杂

这一部分也是本章核心。

主要有：

3. 吞吐量
4. 时延

资料明确将速率、带宽、吞吐量、时延、时延带宽积、RTT 和信道利用率列为重点，其中时延计算尤其高频。

## 二十一、速率

也叫：

- 数据率
- 比特率
- 数据传输速率

单位：

```text
bit/s
b/s
bps
```

注意：

$$
1\text{B}=8\text{bit}
$$

这是超级常见失分点。

比如一个 1000 B 分组：

$$
1000\times8=8000\text{bit}
$$

## 二十二、单位换算是一个巨大坑

网络速率一般：

$$
1\text{kb/s}=10^3\text{b/s}
$$

$$
1\text{Mb/s}=10^6\text{b/s}
$$

$$
1\text{Gb/s}=10^9\text{b/s}
$$

而存储容量常见：

$$
1\text{KiB}=2^{10}\text{B}
$$

考题如果写 KB，有时要结合题意判断采用哪套约定。

所以做题时第一件事情：

> **检查 B/b，检查 1000/1024**。

## 二十三、带宽

这个词有两个含义。

### 通信原理里

表示频率范围：

单位 Hz。

### 计算机网络里

通常指：

> **单位时间内链路理论上能够传送的最大比特数**。

单位：

```text
bit/s
```

例如：

```text
100 Mb/s 链路
```

意味着理论最高发送能力约为每秒 100 Mbit。

## 二十四、吞吐量

吞吐量是：

> **实际单位时间通过的数据量**。

所以：

```text
带宽：理论上限
吞吐量：实际成绩
```

例如：

```text
链路带宽：1 Gb/s
实际吞吐量：700 Mb/s
```

完全正常。

## 二十五、瓶颈链路

假设：

```text
主机
 ↓
1Gb/s
 ↓
100Mb/s
 ↓
500Mb/s
 ↓
主机
```

最大的端到端吞吐量不会是：

```text
1Gb/s
```

而是受最慢的一段限制：

$$
\boxed{
R_{\text{端到端}}
=
\min(R_1,R_2,\ldots,R_n)
}
$$

这里：

$$
R_{\text{端到端}}=100\text{Mb/s}
$$

就是所谓：

> **瓶颈链路**。

## 二十六、★★★★★ 时延的四个组成部分

总时延：

$$
\boxed{
T=
T_{\text{发送}}
+
T_{\text{传播}}
+
T_{\text{处理}}
+
T_{\text{排队}}
}
$$

408 中最重要的是前两个。

## 二十七、★★★★★ 发送时延

发送时延的意思：

> 把一个分组所有 bit 全部“推入链路”需要多久。

公式：

$$
\boxed{
T_t=\frac{L}{R}
}
$$

L 是分组长度。

R 是发送速率。

例如：

```text
分组 1000B
链路 100Mb/s
```

先转 bit：

$$
L=1000\times8=8000\text{bit}
$$

于是：

$$
T_t
=
\frac{8000}{100\times10^6}
=
0.08\text{ms}
$$

## 二十八、★★★★★ 传播时延

传播时延：

> 一个 bit 在物理介质中从这一端跑到另一端需要多久。

公式：

$$
\boxed{
T_p=\frac{D}{V}
}
$$

D 是距离。

V 是信号传播速度。

## 二十九、发送时延和传播时延必须彻底分开

这是第一章最大的概念坑之一。

### 发送时延

由：

```text
数据长度
链路速率
```

决定。

与物理距离无关。

### 传播时延

由：

```text
物理距离
信号传播速度
```

决定。

与数据大小基本无关。

所以：

> **文件变大 → 发送时延变大**。

> **北京到纽约距离变大 → 传播时延变大**。

不要反过来。

## 三十、处理时延

路由器收到数据以后：

```text
检查首部
检错
查路由表
决定输出端口
```

这些都需要时间。

## 三十一、排队时延

比如：

```text
        ┌P1
输入 → 路由器 ├P2
        ├P3
        └P4
```

输出链路正在忙。

P2、P3、P4 就必须等。

这个等待就是：

> 排队时延。

它最难预测，因为取决于网络拥塞程度。

所以多数基础计算题如果没有特别说明：

> 通常忽略处理时延和排队时延。

资料也是这样提示的。

## 三十二、★★★★★ 时延带宽积

公式：

$$
\boxed{
\text{时延带宽积}
=
\text{传播时延}\times\text{带宽}
}
$$

单位：

```text
bit
```

它表示：

> **此时能够“在链路上飞着”的比特数量**。

可以把链路理解为管道：

```text
        链路带宽
        ↓
     ┌───────────┐
发送 → ●●●●●●●●● → 接收
     └───────────┘
        ←传播时延→
```

带宽决定：

> 管子有多“粗”。

传播时延决定：

> 管子有多“长”。

因此：

> 时延带宽积 = 管子能装多少 bit。

## 三十三、RTT

RTT：

**Round Trip Time，往返时延**。

表示：

```text
A → B → A
```

一个很短的探测信息来回一趟所经历的时间。

理想情况下：

$$
RTT\approx2T_p
$$

实际还可能包含：

- 路由器处理时延
- 排队时延
- 接收方处理时延

资料特别提醒：RTT 本身的概念重点是往返过程，不应简单把一个大数据分组完整发送时间机械当作 RTT。

## 三十四、信道利用率

定义：

$$
\boxed{
U=
\frac{\text{信道实际传数据时间}}
{\text{总时间}}
}
$$

注意：

> 利用率不是越接近 100% 越好。

如果一条路始终满载：

```text
█████████████████████
```

后续数据只能：

```text
排队
排队
排队
```

于是排队时延急剧增大。

所以网络设计通常不是简单追求“100% 占满”。

## 三十五、★★★★★ 体系结构为什么一定要分层？

现在进入第二大部分。

假如没有分层，我们要一次性解决：

```text
信号怎么传
帧怎么组织
MAC怎么找
IP怎么路由
端口怎么找到进程
数据是否可靠
格式怎么转换
应用如何使用
```

一个系统会复杂得无法维护。

所以采用：

```text
分层
```

核心思想：

> **把复杂问题拆成多个相对独立的小问题**。

资料中将网络体系结构定义为各层及其协议的集合，并特别强调：

> 体系结构描述“做什么”，而不规定具体“怎么实现”。

这一点是 2010 真题考过的。

## 三十六、体系结构 ≠ 实现

非常重要。

比如：

> 网络层必须完成路由选择。

这是：

```text
体系结构
```

但是：

> 路由表具体用什么数据结构？

> 软件用 C 还是 Rust？

> 路由算法代码怎么写？

属于：

```text
实现
```

因此：

> **体系结构关心功能和协议，不关心具体代码实现**。

## 三十七、实体、对等实体

#### 实体

某一层真正工作的软件或硬件对象。

#### 对等实体

不同机器的同一层实体。

例如：

```text
主机A                     主机B

应用层 ←────逻辑通信────→ 应用层
传输层 ←────逻辑通信────→ 传输层
网络层 ←────逻辑通信────→ 网络层
链路层 ←────逻辑通信────→ 链路层
物理层 ─────真实介质───── 物理层
```

A 的传输层和 B 的传输层：

> 对等实体。

A 的传输层和 B 的网络层：

> 不是对等实体。

## 三十八、★★★★★ 协议、服务、接口

这三个概念必须完全区分。

资料特别强调：**协议是水平的，服务是垂直的**。

### 1. 协议

协议：

> **对等实体之间通信的规则**。

所以：

```text
A传输层 ←────协议────→ B传输层
```

是横向关系。

## 三十九、协议的三要素

这是 408 直接考点，资料标注“同步”在 2020 年考查。

协议三要素：

```text
语法
语义
同步
```

#### 语法

> 数据长什么样？

比如：

```text
前16bit是什么
后32bit是什么
字段怎么排列
```

#### 语义

> 每一部分是什么意思、收到之后做什么？

例如：

```text
SYN=1
```

到底代表什么？

收到后应该怎么处理？

这是语义。

#### 同步 / 时序

> 谁先发？什么时候发？按什么顺序发生？

比如：

```text
A → SYN
B → SYN+ACK
A → ACK
```

这种先后顺序属于：

> 同步。

最简单的记忆：

```text
语法：长什么样
语义：什么意思
同步：什么时候、什么顺序
```

## 四十、接口

接口发生在：

> **同一机器，相邻两层之间**。

```text
应用层
   ↑
  接口
   ↓
传输层
```

具体通过服务访问点：

```text
SAP
```

访问。

所以：

```text
协议：不同机器、同一层
接口：同一机器、相邻层
```

## 四十一、服务

服务：

> **下一层给上一层提供的能力**。

例如：

```text
应用层
   ↑
传输层给应用层提供服务
   ↑
网络层给传输层提供服务
   ↑
数据链路层给网络层提供服务
```

因此：

> 服务是纵向的。

## 四十二、协议和服务之间的关系

这是很容易绕的地方。

第 n 层：

```text
一方面：
使用第 n-1 层的服务

另一方面：
与对方第 n 层按照第 n 层协议通信

最终：
向第 n+1 层提供服务
```

所以：

```text
                第n+1层
                   ↑
                 服务
                   ↑
主机A 第n层 ←协议→ 主机B 第n层
                   ↑
                 服务
                   ↑
                第n-1层
```

一句话：

> **靠下层服务，实现本层协议，再给上层提供服务**。

## 四十三、服务类型

资料总结了三个分类角度。

### 面向连接 / 无连接

#### 面向连接

```text
建立连接
↓
通信
↓
释放连接
```

典型类比：

> 打电话。

#### 无连接

直接发送：

```text
数据1 → 地址B
数据2 → 地址B
数据3 → 地址B
```

类似：

> 寄信。

## 四十四、可靠 / 不可靠

这和“是否面向连接”不是一个维度。

#### 可靠服务

系统保证：

- 正确
- 完整
- 有序

通常依靠：

- 检错
- ACK
- 超时
- 重传
- 序号等

#### 不可靠服务

所谓不可靠，不是：

> “一定会丢。”

而是：

> **协议不承诺一定正确交付**。

例如 IP：

> 尽最大努力交付。

## 四十五、一个特别重要的结论

**下层不可靠，不意味着上层也不能可靠**。

例如：

```text
IP
无连接、不可靠
       ↓
TCP
面向连接、可靠
```

为什么？

因为 TCP 可以自己加入：

- 序号
- 确认
- 超时
- 重传
- 流量控制

因此：

> 上层完全可以利用不可靠的下层，构造可靠服务。

配套题也专门考过这个思想。

## 四十六、★★★★★ OSI 七层模型

从下往上：

```text
7 应用层
6 表示层
5 会话层
4 传输层
3 网络层
2 数据链路层
1 物理层
```

建议一定按照：

> **物、链、网、传、会、表、应**

记。

## 四十七、物理层

核心问题：

> **0 和 1 到底怎么在物理介质上传**？

主要规定：

- 电压
- 信号
- 接口
- 引脚
- 机械特性
- 电气特性
- 传输比特流

PDU 可以理解成：

```text
bit
```

典型设备：

> 集线器 Hub。

因此资料真题中的经典设备层次：

```text
Hub → 1层
Switch → 2层
Router → 3层
```

2016 真题就直接考过。

## 四十八、数据链路层

关键词：

> **相邻节点**。

它解决：

```text
A ───── B
```

这一段链路上的数据传输问题。

典型功能：

- 组帧
- 差错检测
- 流量控制
- 介质访问控制

数据单位：

> 帧 Frame。

典型设备：

> 二层交换机。

## 四十九、网络层

关键词：

> **路由选择**。

比如：

```text
A
│
R1 ─ R2
│     │
R3 ─ R4
      │
      B
```

到底：

```text
A → R1 → R2 → R4 → B
```

还是：

```text
A → R1 → R3 → R4 → B
```

这是网络层。

典型功能：

- 路由选择
- 分组转发
- 网际互联
- 拥塞相关控制

典型协议：

> IP。

典型设备：

> Router。

## 五十、传输层

这是整个 OSI 中一个非常重要的层。

资料中的经典真题：

> OSI 中，自下而上第一个提供端到端服务的是哪一层？

答案：

> **传输层**。

### 为什么不是网络层？

网络层主要负责：

```text
主机 → 主机
```

传输层进一步负责：

```text
进程 → 进程
```

例如同一台电脑同时运行：

```text
Chrome
微信
QQ
Steam
```

数据到了电脑以后：

> 到底交给哪个程序？

这是传输层要解决的问题。

因此传输层常和：

> 端口号

联系在一起。

## 五十一、会话层

关键词：

> **会话管理**。

包括：

- 建立会话
- 维护会话
- 释放会话
- 同步
- 检查点
- 恢复

例如一个很长的数据交换：

```text
─────────检查点─────────检查点─────────
```

中间发生故障，不一定从头开始。

## 五十二、表示层

关键词：

> **数据表示**。

解决：

- 编码转换
- 格式转换
- 加密
- 解密
- 压缩
- 解压缩

比如：

```text
主机A采用一种字符编码
主机B采用另一种表示方式
```

表示层负责解决“怎么解释这些数据”。

资料中 2013、2019 等题都考到这一层与会话层的功能边界。

## 五十三、应用层

最靠近用户。

负责：

> 为具体网络应用提供服务。

例如：

- Web
- 邮件
- 文件传输
- 域名解析

后面会学习：

- HTTP
- FTP
- SMTP
- DNS

这些都是应用层协议。

## 五十四、七层功能最好这样记

| 层     | 核心问题         |
| ----- | ------------ |
| 应用层   | 用户要用什么网络服务   |
| 表示层   | 数据用什么格式表达    |
| 会话层   | 对话怎么组织       |
| 传输层   | 数据交给哪个进程     |
| 网络层   | 数据走哪条路到主机    |
| 数据链路层 | 相邻节点怎么可靠传帧   |
| 物理层   | bit 怎么变成信号传输 |

资料对七层的归纳与此一致。

## 五十五、★★★★★ TCP/IP 四层模型

实际 Internet 使用的体系更接近：

```text
应用层
传输层
网际层
网络接口层
```

与 OSI 对应：

```text
OSI                    TCP/IP

应用层 ┐
表示层 ├────────────→ 应用层
会话层 ┘

传输层 ────────────→ 传输层

网络层 ────────────→ 网际层

数据链路层 ┐
           ├────────→ 网络接口层
物理层     ┘
```

资料将这一对应关系作为明确复习重点。

## 五十六、OSI 和 TCP/IP 最重要的区别

| OSI          | TCP/IP             |
| ------------ | ------------------ |
| 7 层          | 4 层                |
| 理论模型更严谨      | 实际 Internet 广泛使用   |
| 先有模型再设计协议    | 先有 TCP/IP 协议再总结模型  |
| 严格区分服务、接口、协议 | 区分没有 OSI 严格        |
| 网络层可支持连接/无连接 | IP 网际层无连接          |
| 传输层强调面向连接    | TCP/IP 有 TCP 和 UDP |

资料中的模拟题也明确考过：

- OSI 网络层可提供面向连接与无连接服务；
- TCP/IP 网际层主要是无连接的 IP 数据报；
- TCP/IP 传输层同时有 TCP 和 UDP。

## 五十七、五层模型为什么经常出现？

教材讲课时经常用：

```text
应用层
传输层
网络层
数据链路层
物理层
```

它本质上是：

> OSI 和 TCP/IP 的折中教学模型。

它：

- 把 OSI 上面三层合成应用层
- 保留链路层和物理层分离

这样更适合学习。

## 五十八、★★★★★ 封装与解封装

这是理解整个计算机网络最关键的过程之一，资料标注 2021 年考过应用层数据逐层封装。

假设：

> 浏览器产生一段数据。

发送方：

```text
应用层
数据
 ↓
传输层
[传输层首部 | 数据]
 ↓
网络层
[IP首部 | 传输层首部 | 数据]
 ↓
数据链路层
[帧首部 | IP首部 | 传输层首部 | 数据 | 帧尾]
 ↓
物理层
010101010101010...
```

通过链路发送。

## 五十九、接收端做什么？

完全反过来：

```text
bit流
 ↓
数据链路层
去掉帧头/帧尾
 ↓
网络层
去掉网络层首部
 ↓
传输层
去掉传输层首部
 ↓
应用层
得到原始数据
```

所以：

> **发送端：封装**。

> **接收端：解封装**。

## 六十、PDU、SDU、PCI

这三个缩写第一次看很抽象，其实非常简单。

### SDU

Service Data Unit。

> 上层交给本层的数据。

### PCI

Protocol Control Information。

> 本层为了实现协议添加的控制信息。

例如：

```text
首部
尾部
```

### PDU

Protocol Data Unit。

> 本层最终形成的数据单元。

关系：

$$
\boxed{
PDU_n=PCI_n+SDU_n
}
$$

例如传输层：

```text
上层数据
   ↓
    SDU

传输层首部 + 上层数据
      ↓
     PDU
```

## 六十一、常见 PDU 名称

五层模型中建议这样记：

```text
应用层      Message / Data
传输层      Segment（TCP）/ Datagram（UDP）
网络层      Packet / IP Datagram
数据链路层  Frame
物理层      Bit
```

最稳的核心记忆：

```text
数据 → 段 → 分组 → 帧 → bit
```

## 六十二、设备工作层次

非常爱出选择题。

```text
Hub       → 物理层
Switch    → 数据链路层
Router    → 网络层
```

即：

```text
集线器：1
交换机：2
路由器：3
```

2016 真题就是直接这样考。

## 六十三、一个完整的通信过程

最后把全章串起来。

假设：

> 你的电脑访问某服务器。

### 第一步：应用程序产生数据

```text
浏览器
↓
HTTP数据
```

### 第二步：传输层处理

添加传输层控制信息：

```text
[TCP首部 | HTTP数据]
```

解决：

> 数据属于哪个进程、是否需要可靠传输等。

### 第三步：网络层处理

加 IP 首部：

```text
[IP首部 | TCP首部 | HTTP数据]
```

核心：

> 目的主机在哪里？

### 第四步：数据链路层

形成帧：

```text
[帧头 | IP数据报 | 帧尾]
```

解决：

> 当前这一跳怎么传。

### 第五步：物理层

变成：

```text
010101101010...
```

通过：

- 电信号
- 光信号
- 无线电波

传输。

## 六十四、经过路由器时发生什么？

这是后面章节最重要的基础。

例如：

```text
主机A → R1 → R2 → 主机B
```

路由器不会像终点主机一样一路解到应用层。

典型过程：

```text
物理层收到bit
 ↓
链路层得到帧
 ↓
取出IP数据报
 ↓
网络层检查目的IP并查路由表
 ↓
交给新的链路层
 ↓
重新封装成新的帧
 ↓
从下一条链路发送
```

所以可以提前形成一个非常重要的认识：

> **IP 数据报负责端到端跨网络前进，而链路层帧主要负责一跳一跳传输**。

后面讲 MAC 地址、ARP、IP 地址变化问题时，这个思路会非常关键。

## 六十五、历年真题告诉我们应该重点练什么

从你资料里的 408 真题整理可以明显看出，第一章长期反复考：

- **2009**：第一个端到端层 → 传输层
- **2010**：网络体系结构不描述具体实现
- **2011**：TCP/IP 网络层提供无连接、不可靠数据报服务
- **2013**：OSI 相邻层功能
- **2014**：层间服务关系
- **2016**：Router / Switch / Hub 层次
- **2017**：逐层封装造成的有效数据传输效率
- **2019**：会话层功能
- **2020**：协议三要素中的同步
- **2021**：TCP/IP 层次、逐层封装
- **2023/2025 等**：交换和网络时延相关分析

资料中的真题列表与“考点追踪”共同说明：第一章最值得投入时间的不是 LAN/WAN 这种简单记忆，而是 **时延计算 + 分层职责 + 封装过程**。

建议最后把下面这些直接记牢。

| 易错说法         | 正确理解              |
| ------------ | ----------------- |
| 带宽就是吞吐量      | ×，带宽偏理论能力，吞吐量是实际值 |
| 传播时延由带宽决定    | ×，主要由距离和传播速度决定    |
| 发送时延由距离决定    | ×，由数据长度和发送速率决定    |
| 分组越小越好       | ×，首部开销会增加         |
| 报文交换不存储      | ×，整个报文存储转发        |
| 分组交换不存储      | ×，每个分组存储转发        |
| 电路交换也逐跳存储转发  | ×                 |
| 协议是相邻层之间     | ×，协议在对等层之间        |
| 服务是对等层之间     | ×，服务由下层向紧邻上层提供    |
| 网络体系结构规定代码实现 | ×，体系结构描述功能和协议     |
| 网络层是第一个端到端层  | ×，OSI 中是传输层       |
| IP 是可靠连接服务   | ×，IP 是无连接、尽最大努力交付 |

## 六十七、最后压缩成一张“考前背诵图”

```text
【交换】
电路交换：
建立 → 传输 → 释放
独占线路、实时好、利用率低

报文交换：
整个报文存储转发
缓存大、时延大

分组交换：
分组 + 存储转发 + 流水线
Internet核心方式

【时延】
总时延
= 发送 + 传播 + 处理 + 排队

发送时延
= 数据长度 / 发送速率

传播时延
= 距离 / 传播速度

时延带宽积
= 传播时延 × 带宽

【分层】
协议：水平、对等实体之间
服务：垂直、下层 → 上层
接口：同一机器相邻层之间

协议三要素：
语法 + 语义 + 同步

【OSI】
7 应用
6 表示
5 会话
4 传输
3 网络
2 数据链路
1 物理

口诀：
物 链 网 传 会 表 应

【设备】
Hub → 1
Switch → 2
Router → 3

【五层PDU】
应用数据
 ↓
传输层段
 ↓
网络层分组
 ↓
链路层帧
 ↓
物理层bit

【通信范围】
链路层：相邻节点
网络层：主机到主机
传输层：进程到进程

【TCP/IP】

网络接口层
```

如果以 **408 做题能力**为标准，本章最需要做到的是：看到一条多跳链路时，能够立即画出时间线并判断哪里发生发送时延、传播时延和存储转发；看到某个功能时，能立即判断属于哪一层；看到“协议/服务/接口”时，能立刻判断横向还是纵向。把这三件事掌握，本章大多数题基本就稳了。
