---
title: "十字链表及其应用"
description: "十字链表让一个结点同时挂在两条链表上。在有向图中，一条边同时连接弧尾的出边链和弧头的入边链，便于查询顶点的出边、入边、前驱和后继，空间复杂度为 O(|V|+|E|)。它还可用于社交网络、依赖关系、网页链接及稀疏矩阵等场景。"
---

十字链表可以理解成：**让一个结点同时挂在两条链表上**。之所以叫“十字”，就是因为它既能沿一个方向串，又能沿另一个方向串。

在 408 数据结构里，提到“十字链表”，通常主要指**有向图的十字链表存储结构**。它最大的作用是：

> 对一个有向图，既方便找某个顶点的所有出边，也方便找它的所有入边。

---

## 1. 为什么需要十字链表？

先看普通邻接表。

例如有向图：

```text
A → B
A → C
D → A
C → A
```

如果用普通邻接表：

```text
A: B → C
B:
C: A
D: A
```

那么：

* 想找 A 的所有**出边**：很方便，直接看 A 的链表
* 想找 A 的所有**入边**：麻烦

因为要找谁指向 A，只能把所有顶点的邻接表都扫描一遍：

```text
A?
B?
C? 发现 C → A
D? 发现 D → A
```

所以普通邻接表天然偏向：

> “从这个顶点出发能去哪？”

但有时候我们还经常需要：

> “哪些顶点能到这个顶点？”

于是十字链表就出来了。

---

# 2. 十字链表的核心思想

对于一条有向边：

```text
A → B
```

我们希望这条边同时属于两条链：

```text
A 的出边链表
B 的入边链表
```

也就是说：

```text
        A → B
        ↑   ↑
        │   │
      出边  入边
```

同一条边，同时被两个顶点“管理”。

所以叫：

> 十字链表 Orthogonal List

---

# 3. 十字链表有两种结点

主要有：

1. 顶点结点
2. 边结点

---

## 3.1 顶点结点

每个顶点大概保存：

```c
struct Vertex {
    Data data;

    Edge *firstIn;
    Edge *firstOut;
};
```

两个关键指针：

```text
firstIn
```

表示：

> 第一条指向我的边

也就是第一条**入边**。

而：

```text
firstOut
```

表示：

> 第一条从我出发的边

也就是第一条**出边**。

因此一个顶点：

```text
              顶点 A
            ┌─────────┐
            │ data=A  │
            │ firstIn │──→ A 的入边
            │firstOut │──→ A 的出边
            └─────────┘
```

---

# 4. 边结点才是重点

对于：

```text
A → B
```

一条边结点通常包含：

```c
struct Edge {
    int tailVex;
    int headVex;

    Edge *headLink;
    Edge *tailLink;
};
```

很多教材写成类似：

```text
tailvex
headvex
hlink
tlink
```

看起来很乱，其实记住两个词就够了。

---

## 4.1 tail：弧尾

例如：

```text
A → B
```

A 是：

```text
弧尾 tail
```

B 是：

```text
弧头 head
```

因此：

```text
tailvex = A
headvex = B
```

---

# 5. 两个 link 是干什么的？

这个最容易混。

对于边：

```text
A → B
```

它既属于：

```text
A 的出边链
```

也属于：

```text
B 的入边链
```

所以需要两个 next 指针。

---

## tailLink

表示：

> 下一条具有相同弧尾的边

换句话说：

> 下一条从 A 出发的边。

例如：

```text
A → B
A → C
A → D
```

可以组成：

```text
A.firstOut
   ↓
A→B → A→C → A→D
```

这些边的共同特点是：

```text
tail 都是 A
```

因此用：

```text
tailLink
```

连接。

---

## headLink

表示：

> 下一条具有相同弧头的边

也就是：

> 下一条指向 B 的边。

例如：

```text
A → B
C → B
D → B
```

组成：

```text
B.firstIn
   ↓
A→B
 ↓
C→B
 ↓
D→B
```

共同特点：

```text
head 都是 B
```

所以用：

```text
headLink
```

连接。

---

# 6. 一个完整例子

考虑：

```text
A → B
A → C
C → B
D → B
```

边分别记成：

```text
e1: A → B
e2: A → C
e3: C → B
e4: D → B
```

---

## 出边链

A 有：

```text
A → B
A → C
```

所以：

```text
A.firstOut
    ↓
   e1 ──tailLink──→ e2
```

C：

```text
C.firstOut
    ↓
   e3
```

D：

```text
D.firstOut
    ↓
   e4
```

---

## 入边链

B 有三条入边：

```text
A → B
C → B
D → B
```

所以：

```text
B.firstIn
    ↓
   e1
    │ headLink
    ↓
   e3
    │ headLink
    ↓
   e4
```

C 有：

```text
A → C
```

所以：

```text
C.firstIn
    ↓
   e2
```

---

# 7. 为什么叫“十字”？

现在看一条边：

```text
e1 = A → B
```

它同时存在于：

```text
A 的出边链
```

和：

```text
B 的入边链
```

所以可以想象成：

```text
                 B.firstIn
                     ↓
                     │
A.firstOut → [ A → B ] → A 的其他出边
                     │
                     ↓
                 B 的其他入边
```

横着：

```text
tailLink
```

纵着：

```text
headLink
```

一条边同时处在两条链上。

所以看起来像“十字”。

---

# 8. 十字链表最大的用途

最核心的就是：

## 求顶点出度

比如求 A 的出度。

直接：

```text
A.firstOut
```

然后沿：

```text
tailLink
```

一直数。

复杂度大致是：

$$
O(d^+(A))
$$

其中：

$$
d^+(A)
$$

表示 A 的出度。

---

## 求顶点入度

例如求 B 的入度。

直接：

```text
B.firstIn
```

沿：

```text
headLink
```

遍历。

复杂度：

$$
O(d^-(B))
$$

其中：

$$
d^-(B)
$$

是 B 的入度。

这就是相比普通邻接表最大的优势。

---

# 9. 和邻接表比较

这个很适合考试。

| 存储结构 | 找出边 | 找入边 |
| ---- | --: | --: |
| 邻接表  | 很方便 | 较麻烦 |
| 逆邻接表 | 较麻烦 | 很方便 |
| 十字链表 | 很方便 | 很方便 |

普通邻接表：

```text
顶点 → 所有出边
```

逆邻接表：

```text
顶点 → 所有入边
```

十字链表实际上相当于：

> 把邻接表和逆邻接表结合起来，而且同一条边只建立一个边结点。

---

# 10. 它是不是把边存了两份？

不是。

这是十字链表一个很漂亮的地方。

比如：

```text
A → B
```

只有一个边结点：

```text
e1
```

但 e1 同时被两个链表引用：

```text
A 的出边链
B 的入边链
```

所以不是：

```text
A出边表里存一份
B入边表里又存一份
```

而是：

```text
           ┌──────────┐
A ────────→│ A → B    │←──────── B
           └──────────┘
```

一个结点，两个方向链接。

---

# 11. 空间复杂度

假设：

```text
|V| = n
|E| = e
```

那么：

* 每个顶点一个顶点结点
* 每条边一个边结点

所以总空间：

$$
O(|V|+|E|)
$$

和邻接表属于同一个量级。

对于**稀疏图**：

$$
|E| \ll |V|^2
$$

比邻接矩阵：

$$
O(|V|^2)
$$

省很多空间。

---

# 12. 实际适合什么场景？

假设有一个关注关系：

```text
A 关注 B
```

看成：

```text
A → B
```

经常有两种查询：

```text
A 关注了谁？
```

这是找 A 的出边。

同时还经常：

```text
谁关注了 B？
```

这是找 B 的入边。

因此概念上特别适合：

```text
社交网络
依赖关系
调用关系
任务依赖图
网页链接
课程先修关系
```

例如课程：

```text
高数 → 概率论
高数 → 数值分析
线代 → 数值分析
```

想查询：

```text
高数是哪些课程的前置课？
```

找出边。

想查询：

```text
数值分析需要哪些前置课程？
```

找入边。

十字链表两边都方便。

---

# 13. 在图算法中的应用

十字链表尤其适用于需要频繁同时访问**前驱和后继**的有向图算法。

例如：

### 拓扑排序相关处理

一方面需要：

```text
顶点的入边
```

另一方面可能需要：

```text
删除顶点之后处理所有出边
```

十字链表就比较方便。

---

### 有向图动态修改

比如删除：

```text
A → B
```

因为这个边结点同时处在：

```text
A 的出边链
B 的入边链
```

可以分别从两个方向维护结构。

---

### 查前驱 / 后继

比如：

```text
A → C
B → C
C → D
C → E
```

想找 C 的前驱：

```text
A、B
```

沿：

```text
firstIn
```

找。

想找 C 的后继：

```text
D、E
```

沿：

```text
firstOut
```

找。

非常自然。

---

# 14. 十字链表和邻接多重表别混

这是 408 特别容易混的一组。

一般记：

```text
有向图 → 十字链表
无向图 → 邻接多重表
```

为什么？

有向边：

```text
A → B
```

两个端点地位不一样：

```text
A = 弧尾
B = 弧头
```

所以适合十字链表：

```text
出边链 + 入边链
```

而无向边：

```text
A — B
```

两端没有“头尾”。

所以一般用：

> 邻接多重表。

---

# 15. 还有另一种“十字链表”

你以后可能还会在**稀疏矩阵**里看到“十字链表”。

思想其实完全一样。

比如一个非零元素：

$$
a_{ij}
$$

它同时属于：

```text
第 i 行
```

和：

```text
第 j 列
```

于是一个元素结点同时有：

```text
right → 同一行下一个非零元素
down  → 同一列下一个非零元素
```

例如：

```text
        列链
         ↓
      [aij] → 行链
         ↓
```

所以依然是：

> 一个结点同时处在横向链和纵向链中。

这说明“十字链表”本质不是专属于图，而是一种设计思想：

> **一个对象同时属于两个不同维度的链表。**

---

# 16. 你考试时可以这样记

看到**有向图十字链表**，脑子里直接出现：

```text
顶点：
firstIn     → 入边
firstOut    → 出边

边：
tailVex     → 弧尾
headVex     → 弧头

tailLink    → 下一条相同弧尾的边
headLink    → 下一条相同弧头的边
```

最关键口诀：

> **尾连出边，头连入边。**

即：

```text
tail → 出
head → 入
```

于是：

```text
tailLink → 出边链
headLink → 入边链
```

---

## 最后用一张图把它彻底记住

有：

```text
A → B
A → C
D → B
```

那么大致结构就是：

```text
A.firstOut
   │
   ▼
┌─────────┐  tailLink  ┌─────────┐
│  A → B  │───────────→│  A → C  │
└─────────┘             └─────────┘
     │
     │ headLink
     ▼
┌─────────┐
│  D → B  │
└─────────┘
```

同时：

```text
B.firstIn
    │
    ▼
 A→B
  │
  ▼
 D→B
```

因此一句话概括：

> **十字链表就是让有向图中的每一条边同时挂在“弧尾的出边链”和“弧头的入边链”上，从而可以同时高效地找一个顶点的前驱和后继、入边和出边。**

如果你正在学 408，十字链表真正容易出题的地方其实不是定义，而是**给一张有向图，让你判断 `firstIn / firstOut / hlink / tlink` 到底指谁，以及和邻接表、邻接多重表的区别**。这部分我也可以接着用一道具体图把指针一个一个画出来。
